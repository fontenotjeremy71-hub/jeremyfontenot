Windows Server · Hyper-V · Storage administration

APP01 virtual-disk expansion and data-volume provisioning

Expanded a nested Hyper-V virtual disk from 64 GB to 100 GB, safely resolved an active checkpoint chain, preserved the Windows recovery partition, and provisioned the additional capacity as a validated NTFS data volume.

Validated APP01

Objective

Increase usable storage on APP01 while maintaining a supported Windows Server configuration and retaining recovery functionality.

Hyper-V Windows Server 2022 VHDX GPT NTFS PowerShell
Initial state
64 GB dynamic VHDX with an active Hyper-V checkpoint and a 63.37 GB C: volume.
Final state
100 GB dynamic VHDX with C: preserved, the 524 MB recovery partition retained, and a new 36 GB NTFS Data (D:) volume.
Boundary
Personal nonproduction nested-virtualization lab. This does not demonstrate production change-control authority or enterprise storage scale.

Implementation

Change workflow

1. Checkpoint assessment

Identified that APP01 was attached to an .avhdx differencing disk and traced it to the parent HVTEST01.vhdx.

2. Checkpoint merge

Deleted the checkpoint through Hyper-V Manager, waited for the merge to complete, verified that no checkpoints remained, and confirmed APP01 was again attached to the base VHDX.

3. VHDX expansion

Powered off APP01 and expanded the dynamic virtual disk from 64 GB to 100 GB using the Hyper-V Edit Virtual Hard Disk wizard.

4. Partition assessment

Determined that the recovery partition sat between C: and the new unallocated space, preventing Disk Management from extending C: with built-in tools.

5. Data-volume provisioning

Reassigned the DVD drive from D: to E:, created a new simple volume in the unallocated space, formatted it as NTFS, assigned D:, and labeled it Data.

6. Validation

Verified the 100 GB disk, partition layout, healthy NTFS volume, and successful write operation to D:\APP01-storage-validation.txt.
