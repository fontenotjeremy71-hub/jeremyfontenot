Skill

Service Catalog fulfillment

Worked across Request (REQ), Requested Item (RITM), approval, and Catalog Task (SCTASK) records while preserving requester, approver, Procurement, and Field Services responsibilities.

Observed result

Workflow completed automatically

After the final Field Services task was closed complete, ServiceNow automatically completed the RITM and then closed the parent request because all line items were complete.

Workflow

Request → approval → procurement → deployment → completion

Request and approval

A Standard Laptop request generated REQ0010001 and RITM0010001. David Loo approved the requested item, after which ServiceNow automatically created Procurement task SCTASK0010001.

Assignment troubleshooting

A dedicated procurement.agent lab identity was added to Procurement but initially could not be selected in Assigned to. Inspection of the Task assigned-to reference configuration identified an itil role requirement. Granting the required role resolved the invalid-reference condition without weakening the platform qualifier.

Procurement fulfillment

The Procurement Agent experience was validated through impersonation. Because no stock asset was established, the request used a vendor-order lab scenario. Backorder status, estimated delivery, internal work notes, and a customer-visible fulfillment update were recorded.

Deployment and closure

Closing Procurement advanced the RITM to Deployment and created SCTASK0010002 for Field Services. A separate field.services.agent identity completed the simulated deployment. The Configuration item remained blank because no legitimate CI or physical asset was created.

Validation

Automatic lifecycle behavior

  • Procurement task automatically followed approval.
  • Deployment task automatically followed Procurement completion.
  • RITM automatically changed to Closed Complete / Completed.
  • Parent REQ automatically changed from Open to Closed Complete.
  • The RITM and REQ were not manually forced closed.
