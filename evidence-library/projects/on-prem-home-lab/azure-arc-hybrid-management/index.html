Role of Proxmox

Proxmox supplies the QEMU virtualization layer. Both Arc-enabled Windows servers remain running as personal-lab virtual machines; Azure Arc does not replace or directly manage the hypervisor.

Role of Windows Admin Center

Windows Admin Center provides the local connection inventory and Azure integration surface. Its connection list shows both HVHOST01 and VMM01 with Azure Arc status Connected.

Identity separation

The Windows Admin Center gateway uses an on-premises Windows identity, while Azure integration uses a separate Azure identity. Public screenshots redact both account names and the email address while preserving the visible signed-in states.

Resource-group and RBAC boundary

The collected resources are grouped under rg-hybrid-lab-centralus-01. The current evidence does not enumerate role assignments, so it supports resource-group scope but makes no claim about a specific Owner, Contributor, or custom Azure RBAC role.

Onboarding and troubleshooting

Validate the missing agent, use the generated script, and verify the resulting Azure resource.

1. Connectivity before installation

The Windows Admin Center workflow initially appeared to stall while installing the Arc agent. Direct validation found that the Connected Machine agent executable was absent, while outbound TCP 443 connectivity to gbl.his.arc.azure.com succeeded.

2. Manual onboarding script

The Azure-generated onboarding script was transferred to VMM01 and executed through the authorized PowerShell remoting path. The agent installed, authenticated, created the Azure resource, and reported Connected.

3. Agent and service validation

Fresh direct validation on HVHOST01 confirmed agent version 1.67.03504.3207, Connected status, enabled agent auto-upgrade, successful TCP 443 reachability, and the himds, ExtensionService, and GCArcService services running with Automatic startup.

4. Current access limitation

VMM01 answered WinRM but rejected the current Windows credential for a fresh remote session. Its local Arc and SQL services were not re-read directly during this collection; Azure portal and Windows Admin Center supplied the current connected, extension, SQL inventory, licensing, and telemetry evidence.

SQL Server discovery and extension

Move from a pending extension to a connected SQL inventory record.

Initial extension state

The SQL extension initially remained in Creating/ENABLING while the SqlServerExtension service was StartPending. Onboarding logs showed least-privilege configuration and local-group membership work still in progress.

Observed resolution

The service later reached Running, the WindowsAgent.SqlServer extension reached Succeeded, SQL inventory appeared, and DPS upload status reached OK. The current portal evidence shows extension version 1.1.3518.465 with automatic upgrade enabled.

Licensing decision

The Arc-enabled SQL resource reports SQL Server 2022 Developer edition. License only is selected instead of pay-as-you-go; Developer edition is not presented as production licensed.

Services not inferred

Azure Monitor, Azure Backup, Update Manager, Defender, Site Recovery, automated SQL updates, and automatic SQL backups are not described as enabled. The SQL overview explicitly showed automated updates and automatic backups Disabled.

Limitations and next steps

A verified hybrid-management lab, not a production Azure operations claim.

The evidence supports two Arc-connected Windows Server lab machines, one Arc-enabled SQL Server 2022 Developer instance, current extension and telemetry states, and direct HVHOST01 agent/service validation. It does not prove production administration, enterprise scale, broad Azure RBAC ownership, high availability, disaster recovery, SLA performance, security assurance, or enabled Azure services beyond the fields shown. VMM01 local service state was not freshly read because the current Windows credential was rejected.

Practical next steps are to restore an approved VMM01 remoting path, repeat the local service and SQL checks, document the exact Azure RBAC assignment through a public-safe export, and evaluate optional Azure services separately before making any enablement claim.
