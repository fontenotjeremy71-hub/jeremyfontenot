Implementation and troubleshooting

Build, remediate, onboard, and verify.

01

Server and database foundation

Prepared VMM01 on Windows Server 2022 and installed SQL Server 2022 Developer as the local database platform for the VMM management server.

02

ADK and WinPE prerequisites

Installed Windows ADK Deployment Tools and the Windows PE add-on. When VMM could not locate the Component Studio libraries, verified that the DLLs existed under WSIM\amd64 and copied the WSIM architecture files into the root path expected by Setup.

03

Dedicated service identity

Created JFAD\svc_scvmm, configured the account for the lab service role, added it to VMM01's local Administrators group, and used it for the Virtual Machine Manager service.

04

SCVMM installation

Installed both the SCVMM 2022 management server and VMM console, configured the local VMM database and library, retained standard service ports, and verified a successful console connection to VMM01.

05

Hyper-V host onboarding

Added HVHOST01 as a trusted-domain Hyper-V host. The first agent deployment exposed an unreachable ADMIN$ path; TCP 445 testing isolated the firewall block, File and Printer Sharing was enabled, and the retry completed with host status OK.

06

VM discovery and control

SCVMM discovered APP01 on HVHOST01. Remote power-on completed successfully, guest information populated, and VM Viewer confirmed an interactive APP01 console session.

07

Laptop console over OpenVPN

Installed only the VMM console MSI on Jeremy's non-domain-joined laptop, connected to VMM01 with domain credentials through OpenVPN, and validated TCP 8100 access plus APP01 control and console viewing.

08

Temporary access cleanup

Removed the temporary SCVMM installer SMB share, deleted the laptop's cached SMB connection, and removed the temporary OpenVPN TCP 445 rule. TCP 8100 remains as the scoped VMM console path.

Scope and limitations

A working management lab, not an enterprise VMM deployment.

The evidence supports a single SCVMM 2022 management server, one managed nested Hyper-V host, one discovered guest, remote lifecycle control, VM Viewer access, and a scoped OpenVPN console path. It does not prove clustering, high availability, live migration, Storage Spaces Direct, enterprise scale, production availability, security assurance, or management of Proxmox guests through VMM.
