Validated Microsoft systems administration project

Windows LAPS & Advanced Group Policy

Implemented and validated modern Windows LAPS in a Windows Server 2022 Active Directory lab, including schema extension, OU scoping, Group Policy, encrypted local-administrator password storage, least-privilege retrieval, RSOP, event-log troubleshooting, and forced password rotation.

What this proves

Windows administration skills that transfer directly to junior systems work.

This project connects endpoint security to the Active Directory and Group Policy administration tasks commonly handled by Windows infrastructure teams.

AD

Directory administration

Inspected schema state before change, temporarily elevated only for the required schema operation, validated the new attributes, and removed the temporary privilege afterward.

GPO

Policy engineering

Built a dedicated OU and GPO scope, configured password backup, complexity, age, encryption, authorized decryptors, and a named managed local account, then validated policy application with gpresult and RSOP.

IAM

Least-privilege delegation

Separated LAPS password-read rights from broader administration by using a dedicated security group and a non-admin reader account, then proved that an unauthorized standard user could not retrieve the record.

OPS

Evidence-driven troubleshooting

Used LAPS Operational events, WMI testing, firewall policy-source checks, PowerShell remoting, and controlled negative tests to identify the failing layer before making changes.

Architecture

Isolated scope with explicit delegation.

OU

Dedicated test scope

WS01 was moved into a protected LAPS-Test OU beneath Workstations so the control could be deployed and validated without unnecessarily changing the rest of the lab.

PWD

Encrypted credential storage

Windows LAPS backs the managed LocalAdmin password to Active Directory using encrypted LAPS attributes, with a 30-day age and 14-character complex password policy.

ACL

Authorized decryptor

Password-read permission is delegated to JFAD\GG-LAPS-Password-Readers. The built-in RID-500 Administrator account remains disabled.

VAL

Multiple validation layers

Validation included AD attributes, GPO application, RSOP, event logs, delegated retrieval, an unauthorized negative test, and administrator-initiated password rotation.

Troubleshooting demonstrated

The project includes diagnosis, not just configuration.

Managed-account correction

LAPS initially targeted the disabled built-in Administrator account. Local account state and Event ID 10067 were used to identify the issue, then the policy was changed to manage the existing enabled LocalAdmin account.

RSOP / WMI remediation

Group Policy Results initially failed with RPC error 0x800706BA. Direct WMI testing isolated the problem to disabled local WMI firewall rules on WS01; enabling only the Domain-profile rules restored WMI and RSOP.

Remote-access diagnosis

TCP 3389 testing proved the DC was reachable before local mstsc.exe AppHang evidence identified the RDP client as the failing layer. An alternate clean client invocation succeeded.

Secure evidence handling

Validation output intentionally records account name, timestamps, encryption source, decryption status, authorized decryptor, and event IDs while excluding the managed password itself.
