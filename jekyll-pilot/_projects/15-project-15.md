<section id="architecture" class="section"><h2>Architecture &amp; execution model</h2><p>A locally hosted dashboard presents eight administration cards. Seven validated workflows expose <strong>Run</strong>, <strong>Edit</strong>, and <strong>View Log</strong> actions. A custom <code>jf-script://</code> protocol is routed through a PowerShell launcher, with a shared protocol handler and execution wrapper. Execution results are retained as timestamped logs for repeatable troubleshooting and review.</p><div class="tags"><span class="tag">PowerShell 7</span><span class="tag">Windows administration</span><span class="tag">Microsoft Graph</span><span class="tag">Entra ID</span><span class="tag">Intune</span><span class="tag">Windows LAPS</span><span class="tag">Active Directory</span></div><p>The dashboard is a <strong>local administration interface</strong>, not a public remote-command service. Its eighth card, portfolio validation, is reserved for integration with the repository's validation suite.</p><aside class="project15-publication-note" aria-label="Current website publication architecture"><p class="project15-eyebrow">Current portfolio publication</p><h3>Jekyll + GitHub Actions</h3><p>The public portfolio is now generated using Jekyll and published through GitHub Actions with automated build, link, evidence, and browser checks. This publishing pipeline is separate from the locally hosted dashboard shown in the original captures. The reserved dashboard validation card is retained here as part of the documented interface; it is not presented as an active website-deployment control.</p></aside></section>

<section id="validation" class="section project15-section"><h2>Observed validation results</h2><p>Original PowerShell console screenshots captured successful checks for <strong>Cloud Sync / AD state</strong>, <strong>Entra role inventory</strong>, <strong>Microsoft 365 tenant inventory</strong>, <strong>Intune managed-device inventory</strong>, and <strong>Windows LAPS</strong>. The five original validation screenshots are published below as directly accessible PNG evidence. The broader dashboard workflow also includes Azure Arc validation and guarded AD provisioning.</p><p>Validation screenshots show command output and PASS results; they do not imply production tenant administration or unattended write access.</p><p class="project15-proof-note"><strong>Evidence standard:</strong> These original PASS captures document specific test outcomes at capture time; they are not claims about the current state of a tenant or live infrastructure.</p></section>
