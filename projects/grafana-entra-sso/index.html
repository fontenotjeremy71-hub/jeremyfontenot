Grafana OSS + Microsoft Entra Single Sign-On

Nonproduction hybrid identity lab: secure a Linux-hosted application and validate cloud SSO end-to-end.

Architecture and objective

Grafana OSS 13.3.0 runs on Ubuntu 26.04 LTS LINUX01 at 10.10.30.20 in an isolated home-lab Linux VLAN. Windows endpoint LT-JF01 reaches Grafana over pfSense OpenVPN. Active Directory DNS on DC01 resolves grafana.ad.jeremyfontenot.online to the private server address. This is a personal, nonproduction implementation—not a public Grafana service.

Implementation and troubleshooting

Implementation details below are retained from the interactive lab record. The published screenshots directly substantiate the UI results identified in the gallery; they do not independently verify every server command or configuration setting.

Diagnosed missing VPN route to VLAN 30, restricted Linux UFW SSH access to the VPN subnet, and authenticated to Ubuntu through SSSD using an Active Directory account. Installed Grafana through the signed Grafana APT repository and verified its health endpoint.

Issued a publicly trusted Let's Encrypt certificate through restricted Cloudflare DNS-01 credentials without publishing Grafana to the internet. Configured Grafana HTTPS on port 3000, secure cookies, and root-owned certificate copies readable by the Grafana group. A Certbot deployment hook copies renewed certificate material and restarts Grafana after successful renewal.

Registered single-tenant Grafana-OSS-SSO-Lab in Microsoft Entra; configured Grafana's built-in AzureAD provider, OAuth client credentials from a protected file, PKCE, token refresh, and an HTTPS callback. Kept the local administrator login as a recovery path.

Assigned the Entra test identity to the enterprise application, enabled Assignment required, published a branded Microsoft My Apps tile, and used the tile to launch Grafana.

Observed validation

Authentication and authorization

Microsoft Entra consent flow returned to an authenticated Grafana dashboard. Grafana Profile displayed attributes synchronized via AzureAD and explicitly showed organization role Viewer, despite the account's display name containing “Admin.”

HTTPS and automated renewal — session-documented

Grafana /api/health responded with database ok over certificate-validated HTTPS. Certbot renew --dry-run --run-deploy-hooks succeeded; the hook ran, Grafana stayed healthy, and deployed certificate/key files matched Let's Encrypt originals.

Application access and launch

Entra Enterprise Application showed the user assigned Default Access with Assignment required = Yes. The official Grafana-branded tile appeared in My Apps and opened Grafana. The follow-up profile displayed AzureAD as the session identity provider.
