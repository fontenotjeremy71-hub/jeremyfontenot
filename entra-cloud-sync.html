Microsoft Entra Hybrid Identity & Cloud Sync

Built and validated a Microsoft hybrid identity workflow connecting Windows Server 2022 Active Directory to Microsoft Entra ID through Microsoft Entra Cloud Sync. The project demonstrates scoped identity provisioning, attribute synchronization, Password Hash Synchronization, security-group synchronization, source-anchor correlation, agent-health validation, troubleshooting, and evidence-based administration.

Architecture

On-premises Active Directory remained the identity source of authority.

DC01 provides the Active Directory identity source while SYNC01 runs the Microsoft Entra Cloud Sync provisioning agent. Selected objects from a dedicated Cloud Sync OU are provisioned to Microsoft Entra ID over outbound HTTPS without replacing the existing directory infrastructure.

Operational behavior

Synchronization timing matters during troubleshooting.

The validated Cloud Sync configuration uses a fixed 20-minute provisioning interval for users and groups. Password Hash Synchronization operates separately on a fixed 5-minute interval. A newly created group initially appeared absent because the normal provisioning window had not completed—not because synchronization was broken.

Troubleshooting

Agent health was repaired from evidence instead of rebuilding working infrastructure.

Resolved and validated

Cloud Sync agent metrics permission issue

SYNC01 logged Event ID 12033 indicating that the provisioning agent service account could not access the required performance-counter registry context.

Investigation
Validated the provisioning service account, confirmed SYNC01 was authorized to retrieve the gMSA password, reviewed Cloud Sync event logs, and avoided treating a context-dependent Test-ADServiceAccount result as proof of failure.
Remediation
Added the Cloud Sync gMSA to the local Performance Log Users group on SYNC01 and restarted only the provisioning service.
Result
Event ID 12033 did not recur and Event ID 14013 confirmed successful metrics-agent initialization. Cloud Sync remained operational.
Decision
The working Cloud Sync installation was preserved rather than unnecessarily reinstalling or replacing the synchronization engine.

Design decision

Cloud Sync was retained instead of installing Entra Connect Sync only to gain manual sync control.

Microsoft Entra Cloud Sync was already functioning in the lab and met the project's hybrid identity requirements. Installing another synchronization engine merely to avoid the normal Cloud Sync provisioning interval would add complexity and potential overlap without improving the validated architecture.
